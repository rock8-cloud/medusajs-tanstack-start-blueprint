# AGENTS.md

Instructions for coding agents working in this repository. Read
[README.md](README.md) for what the blueprint *is*; this file is the short list
of things that will break if you ignore them.

## Layout

| Path                       | What lives there                                                         |
| -------------------------- | ------------------------------------------------------------------------ |
| `apps/backend`             | `@dtc/backend` — Medusa 2 server + admin dashboard (`/app`)              |
| `apps/tanstack-storefront` | `@dtc/tanstack-storefront` — TanStack Start storefront (SSR, Tailwind v4) |
| `docker-compose.yml`       | Local Postgres 17 (host port 5433) and Redis 7 (host port 6380)          |

## Architecture rules

- **The storefront talks to Medusa only from server functions.** Every Medusa
  call lives in `apps/tanstack-storefront/src/lib/server/*` (`createServerFn`)
  and goes through the one SDK client in `src/lib/sdk.ts`. The customer JWT and
  the cart id are httpOnly cookies (`src/lib/server/cookies.ts`), so the browser
  can't call Medusa itself. Don't fetch Medusa from components.
- **`VITE_*` variables are build-time and public.** Vite inlines them into the
  browser bundle, so a change needs a rebuild and they must never hold a secret.
  The publishable API key is public by design; nothing else secret goes there.
- **Medusa prices are already in display units.** `calculated_amount` is `10`
  for 10 EUR — never divide by 100 (`src/lib/price.ts`, `src/lib/format.ts`).
- **Backend customizations go in Medusa's own folders**: `src/api` (routes),
  `src/modules` (data models + services), `src/workflows`, `src/subscribers`,
  `src/jobs`, `src/links`, `src/admin` (widgets and pages). Each has a README.
  A new module must be registered in `modules` in `apps/backend/medusa-config.ts`.
- **Redis is required.** `medusa-config.ts` wires the cache, event bus,
  workflow engine and locking modules to `REDIS_URL`; without it the backend
  fails at startup — in `develop`, `start` and `db:migrate` alike.
- **All `@medusajs/*` packages share one pinned version** (`2.21.2`). Upgrade
  them together, then run `medusa db:migrate`.
- **The storefront UI is Czech** (`<html lang="cs">`, `cs-CZ` number and date
  formatting, `czPlural` in `src/lib/format.ts`). Keep new copy consistent.

## Commands

Run at the repository root unless noted; Turborepo fans them out.

| Command                | Notes                                                                 |
| ---------------------- | --------------------------------------------------------------------- |
| `bun install`          | Bun workspaces; commit `bun.lock`                                     |
| `docker compose up -d` | Local Postgres (`:5433`) and Redis (`:6380`)                          |
| `bun run dev`          | Backend `:9000` (admin at `/app`) and storefront `:3333`              |
| `bun run build`        | `apps/backend/.medusa/server` and `apps/tanstack-storefront/dist`     |
| `bun run typecheck`    | `tsc --noEmit` in both apps — run this before you call a change done  |
| `bun run test`         | Storefront unit tests (Vitest)                                        |

Backend database commands run in `apps/backend`:

| Command                                      | Notes                                                            |
| -------------------------------------------- | ---------------------------------------------------------------- |
| `bunx medusa db:migrate`                     | Apply migrations and run migration scripts                       |
| `bunx medusa db:generate <module>`           | Generate a migration after editing a module's data models        |
| `bunx medusa user -e <email> -p <password>`  | Create an admin user                                             |

`src/migration-scripts/initial-data-seed.ts` runs once, on the first
`db:migrate`: it creates the store, the Europe region (EUR), demo products and
the publishable API key the storefront needs.

**The publishable key is pinned.** The seed overwrites Medusa's random token with
`MEDUSA_PUBLISHABLE_KEY` (or the default in the seed), and
`apps/tanstack-storefront/src/lib/sdk.ts` falls back to the same default, so a
fresh deploy needs no key. The default lives in both files — change both
together, or neither. Publishable keys are public; never treat them as secrets
and never pin a secret (`sk_`) key this way.

`apps/tanstack-storefront/src/routeTree.gen.ts` is generated by the TanStack
router plugin and committed so `typecheck` passes on a fresh clone. It
regenerates on `dev` and `build` (or `bun run generate-routes` in the
storefront). Never edit it.

## Environment variables

Local values go in `apps/backend/.env` (from `.env.template`) and
`apps/tanstack-storefront/.env` (from `.env.example`); both are gitignored.
Add any new variable to the matching template. In production the environment
comes from the platform, not from `.env`.

| Variable                      | Used by    | Purpose                                                              |
| ----------------------------- | ---------- | -------------------------------------------------------------------- |
| `DATABASE_URL`                | backend    | Postgres connection string                                           |
| `DATABASE_SSL`                | backend    | `true` for managed Postgres that requires TLS (Rock8Cloud)           |
| `REDIS_URL`                   | backend    | Redis for cache, events, workflows and locks                         |
| `JWT_SECRET`, `COOKIE_SECRET` | backend    | Auth signing secrets — long random values in production              |
| `STORE_CORS`                  | backend    | Storefront origin(s)                                                 |
| `ADMIN_CORS`, `AUTH_CORS`     | backend    | Backend origin (admin) — `AUTH_CORS` also the storefront origin      |
| `MEDUSA_ADMIN_EMAIL`, `MEDUSA_ADMIN_PASSWORD` | backend | Docker only: admin user created on the first boot   |
| `MEDUSA_PUBLISHABLE_KEY`      | backend    | Optional: the `pk_…` token the first seed gives the publishable key  |
| `FORCE_MIGRATE`               | backend    | Docker only: `true` runs `db:migrate` on boot even if already migrated |
| `MEDUSA_WORKER_MODE`          | backend    | `shared` (default), `server` or `worker`                             |
| `DB_POOL_MIN`, `DB_POOL_MAX`  | backend    | Postgres pool bounds (default 2 / 20)                                |
| `VITE_MEDUSA_BACKEND_URL`     | storefront | Backend URL — **build time**                                         |
| `VITE_MEDUSA_PUBLISHABLE_KEY` | storefront | Optional: publishable key (defaults to the pinned one) — **build time** |
| `VITE_DEFAULT_REGION`         | storefront | Country code that picks the region (default `de`) — **build time**   |
| `PORT`                        | both       | Port to bind; injected by Rock8Cloud in production                   |

## Deployment

Rock8Cloud builds each service from a checked-in Dockerfile
(`apps/backend/Dockerfile`, `apps/tanstack-storefront/Dockerfile`), both built
from the repository root with `bun install --frozen-lockfile`, so every
workspace `package.json` is copied before the install. If you change the
workspace layout or a build script, update both Dockerfiles and `.dockerignore`
in the same change. The deployment steps are in the README; `.mcp.json` wires
up the Rock8Cloud MCP server.

- **Migrations only run on a fresh database.** `apps/backend/docker-entrypoint.sh`
  skips `db:migrate` once the database has migrations, to keep boots fast. After
  adding a migration or upgrading Medusa, deploy once with `FORCE_MIGRATE=true`.
- **The backend needs about 1 GiB of memory.** It idles near 460 MiB; the
  platform's default allocation (256 MiB) gets it OOM-killed.
